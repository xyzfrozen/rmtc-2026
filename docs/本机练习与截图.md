# 本机公开裁判练习与前置检录

先完成[迁移与验收](迁移与验收.md)中的构建和源码检查，并准备主办方测试包。测试包不是代码仓库的一部分。此页面向迁移后的默认目录`~/Documents/rmtc-2026`；如果选择了其他目录，由迁移执行者替换下方两条路径，并给本人完整的实际命令。

只复制代码框内部命令，不要复制Markdown外层反引号、`bash`标记或终端提示符。这里使用本机练习域27，须确保同域没有其他对局；所有进程使用`ROS_LOCALHOST_ONLY=1`。正式网线比赛另看[现场启动说明](现场启动说明.md)。

## 第一阶段

终端一（裁判），先设置实际路径，再启动：

```bash
RMTC_REPO="$HOME/Documents/rmtc-2026"
RMTC_PRACTICE="$RMTC_REPO/third_party/dist/rmtc_practice"
ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=1 RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  bash "$RMTC_PRACTICE/start_referee.sh" --stage 1 --tick-ms 100 --max-ticks 100 --bots '' --data-dir "$RMTC_REPO/local/practice"
```

等待“练习裁判已就绪（暂停）”。浏览器打开`http://127.0.0.1:8080`；这才是操作页面。`/v1/chat/completions`是程序使用的POST接口，直接用浏览器GET访问会返回“资源不存在”。

终端二（自己的参赛车）：

```bash
RMTC_REPO="$HOME/Documents/rmtc-2026"
test -f "$RMTC_REPO/config/match.json" || cp "$RMTC_REPO/config/match.example.json" "$RMTC_REPO/config/match.json"
bash "$RMTC_REPO/start.sh" stage1 --local --ros-domain-id 27 --team A --team-name '本机测试'
```

看到`Ready: team=A`后点击网页“开始 / 继续”，100ms×100Tick约10秒。保留启动命令、Ready、实际Tick和网页上本队的动作/执行Tick。第一阶段没有AI调用，不输入令牌。不要开启参考车或另一个程序控制A席位。

程序打印本次`logs/日期时间-stage1-A/`路径。完成后用该**实际路径**查看日志：

```bash
python3 "$HOME/Documents/rmtc-2026/tools/show_precheck.py" '/本次真实完整路径/decisions.jsonl'
```

最后一个参数需替换成启动时真实打印的文件路径；迁移执行者应直接替本人填好。工具只读本队日志，展示同场`tick=N`感知与动作、下一帧`last_action.tick=N`的成功移动回执，不产生比赛数据。没有正确对应关系会报错；不能拿空日志或错误提示作为通过证据。

## 第二阶段

结束第一阶段后，在终端二按Ctrl+C退出采集车。可以在仍运行的裁判网页选择第二阶段，设500ms/500Tick、关闭所有陪练并“部署新练习”；或在终端一Ctrl+C退出裁判后启动：

```bash
ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=1 RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  bash "$RMTC_PRACTICE/start_referee.sh" --stage 2 --tick-ms 500 --max-ticks 500 --bots '' --ai-mode mock --data-dir "$RMTC_REPO/local/practice"
```

终端二启动本队第二阶段车：

```bash
bash "$RMTC_REPO/start.sh" stage2 --local --ros-domain-id 27 --team A --team-name '本机测试' --gateway-url 'http://127.0.0.1:8080/v1/chat/completions'
```

隐藏输入提示出现后输入公开测试令牌`practice-A`并回车；它不是开发API Key或正式令牌。程序Ready后再点击网页开始，500ms×500Tick约4分10秒；正常完成后按前节方法检查本次`stage2-A`的真实日志。

公开练习包v1.1不提供`/healthz`，因此这里直接启动，不使用正式网关的`--check`。本地模拟AI返回固定的`goals/event_plan`结构，不是本程序期待的`events`结构，可能显示HTTP200但本地解释无效；这不影响检验动作链路，也不代表真实模型已成功理解事件。未接入的其他车等待，不能把这个场景当作完整多人强度评测。

## 真实模型验证

先确认本人授权调用费用。要从模拟改成真实模式，需要退出并重启裁判进程；只在网页重开不会改变`ai-mode`。结束当前局再切换，避免丢失完整对局记录。真实上游使用本人在新电脑安全输入的开发凭据，不从代码仓库或旧电脑复制密钥。

在裁判终端先单独执行下面一行，输入开发用DeepSeek Key并回车后再做下一步：

```bash
read -r -s -p '输入开发用DeepSeek API Key：' PRACTICE_LLM_KEY
```

同一终端继续：

```bash
printf '\n'
export PRACTICE_LLM_KEY
export PRACTICE_LLM_URL='https://api.deepseek.com/chat/completions'
export PRACTICE_MODEL='deepseek-flash'
ROS_DOMAIN_ID=27 ROS_LOCALHOST_ONLY=1 RMW_IMPLEMENTATION=rmw_fastrtps_cpp \
  bash "$RMTC_PRACTICE/start_referee.sh" --stage 2 --tick-ms 500 --max-ticks 500 --bots '' --ai-mode real --data-dir "$RMTC_REPO/local/practice"
```

选手仍使用上一节的启动命令和本地练习令牌`practice-A`。模型请求会消耗本人开发API额度，正式比赛由官方网关与本场令牌处理。测试结束退出裁判后执行`unset PRACTICE_LLM_KEY`。

核对真实公开事件的对象、范围、时间、参数和程序接受的解释，不只看HTTP200或`AI interpretation accepted`。单车易伤存在已记录的漏报/时间错误，不能写成全部语义通过。

## 截图证据与边界

参赛手册要求自己的程序编译启动、感知、动作和后续执行回执形成完整链路，没有固定截图张数。建议按编译、第一阶段、第二阶段、真实模型测试四组整理；字段过多可分屏。所有图保留实际版本/路径、阶段和运行来源，不露API密钥或正式令牌。

感知与对应动作的`tick`和`session_id`必须相同；下一帧回执的Tick对应前一帧动作，不是当前感知Tick。只看到话题、网页全图、模型成功响应或自检合成数据都不等于完成官方双向验证。原始本队日志留本地，技术报告和截图由本人按赛事渠道提交。

本机公开练习不替代另一台真实裁判机的网线接入。现场IP、域、席位和令牌必须使用主办方分配值。
