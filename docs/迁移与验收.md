# 另一台Ubuntu电脑的迁移与验收

目的：从GitHub私有仓库取得指定版本，在另一台电脑重新构建、测试并准备本地运行。先复现，再判断环境问题；本任务不调整采集、战斗或事件Prompt。

## 1. 检查系统与账户

只在Ubuntu所在磁盘操作。确认`cat /etc/os-release`为Ubuntu22.04、`uname -m`为x86_64，并检查`/opt/ros/humble/setup.bash`、`git`、`gh`。系统或架构不符时说明差异，不更换系统、不格式化磁盘。

私有仓库需要账户访问权限。推荐使用GitHub CLI：`gh auth status`；未登录时运行`gh auth login`，让本人在浏览器完成授权，然后`gh auth setup-git --hostname github.com`。不要把PAT、SSH私钥、模型密钥或sudo密码贴到聊天、写入README或从旧电脑复制凭据目录。克隆也可使用已经配置好的SSH凭据。

```bash
gh repo clone xyzfrozen/rmtc-2026 "$HOME/Documents/rmtc-2026"
cd "$HOME/Documents/rmtc-2026"
git checkout --detach v1.2-20261030
git rev-parse HEAD
git status --short
python3 tools/verify_source.py
```

如果目标目录已存在，检查是否为此仓库、有无未提交修改；不覆盖或重置现有工作。版本标签和具体提交应与交接提示词一致。不得从其他ROS工作空间运行同名节点。

## 2. 安装缺失依赖

先检查再安装，需要sudo时先说明用途。已经安装ROS Humble且配置好官方APT源时，可按缺件安装下面的软件包：

```bash
sudo apt-get update
sudo apt-get install build-essential cmake pkg-config libjsoncpp-dev libcurl4-openssl-dev python3 iproute2 tzdata ros-humble-ros-base ros-humble-rclcpp ros-humble-std-msgs ros-humble-rmw-fastrtps-cpp ros-humble-rclpy
```

如果尚未配置ROS源，按[ROS 2 Humble官方Ubuntu安装文档](https://github.com/ros2/ros2_documentation/blob/humble/source/Installation/Ubuntu-Install-Debs.rst)及其引用步骤配置Ubuntu22.04的软件源，再安装。不要只因`apt`找不到包就换用其他ROS发行版，不执行整机升级或无关软件卸载。

主办方练习包还用到`python3-requests`、`python3-yaml`、`unzip`、`tar`，按提供的教程补齐。不要使用Conda/venv中的Python替代系统ROS Python；本项目测试入口明确使用`/usr/bin/python3`。

## 3. 构建与基础自检

在克隆的仓库根目录执行：

```bash
bash build.sh
python3 tools/verify_source.py
bash tools/smoke_ros.sh --domain 85
```

预期：第一阶段1项、第二阶段2项CTest通过；两阶段实际节点分别完成注册、20帧合成感知与动作回填，第二阶段本地HTTP请求字段符合当前配置。测试域必须空闲；自检仅绑定本机回环，模拟网关随机分配空闲端口，不调用付费模型。

结果保存在`logs/migration-smoke-*/result.json`。如果同仓库已有参赛程序运行，自检会被单实例锁拒绝；应先停止自己启动的测试进程，不能删除锁文件绕过。自检结束自动停止自己启动的节点和模拟服务。

这只证明基础运行链路，不是正式裁判结算、真实动作回执、默认完整局时序或事件语义测试。

## 4. 准备本地配置与官方练习包

保留已有配置，仅在不存在时复制：

```bash
test -f config/match.json || cp config/match.example.json config/match.json
```

本机练习通过`--local`及`--gateway-url http://127.0.0.1:8080/v1/chat/completions`覆盖网络；正式比赛时填写实际有线网卡和网关。域、席位、队名每次由命令给定，不复制旧电脑网络参数。

请本人把主办方提供的`dist.zip`放到新电脑Ubuntu的Downloads目录。当前已知v1.1包的SHA-256为：

```text
4abe666edddd4d92f5a290ce8175e7f20c1e4bf44c2a83afa7c5b35297051f84
```

此包不在代码仓库中，也没有杜撰的公网下载地址。没有它时，先完成前面的构建与合成自检，向本人说明需要传文件；不能宣称完整裁判测试通过。若本人提供新版，记录新的来源/版本，不把它误当作此哈希对应的包。

对已确认的包：

```bash
mkdir -p third_party
unzip "$HOME/Downloads/dist.zip" -d third_party
cd third_party/dist
sha256sum -c rmtc_practice.sha256
tar -xzf rmtc_practice.tar.gz
```

先检查压缩包内容，不允许绝对路径或`..`越界写入；已有解压目录则复用或另选空目录，不覆盖未知文件。完成后确认实际`start_referee.sh`位置，通常在`third_party/dist/rmtc_practice/`。后续按[本机练习与截图](本机练习与截图.md)测试两阶段。

## 5. 真实模型与实际有线接入

默认先用本地模拟HTTP检查通信。真实事件测试需要本人授权费用并在本机安全输入自己的开发API凭据，保留实际语义结果；HTTP200和结构校验成功不能代替事件正确性。当前单车易伤存在已知语义失败，迁移不修订Prompt。

真实比赛时模型统一`deepseek-flash`，关闭思考、输出上限512，令牌由主办方发放并在启动后隐藏输入。真正的局域网通信还须由本人接网线、取得裁判IP/域/席位及静态IPv4，按[现场启动说明](现场启动说明.md)进行感知—动作—回执检查。没有实际设备和分配值时，不改网络设置、不编造验收。

## 6. 留下迁移结果

在被忽略的`local/迁移验收.md`记录实际Git提交、源码校验、OS/架构、ROS/编译器/库版本、构建和自检结果、真实官方练习的Tick/动作/回执、未完成项目与对应日志路径。只记录已执行的事实；原电脑报告不是新电脑证据。

结束时给本人能直接复制的绝对路径启动命令，清楚区分浏览器操作页`http://127.0.0.1:8080`与程序POST接口`/v1/chat/completions`。没有新的授权，不推送迁移报告、不改仓库可见性或邀请其他账户。
